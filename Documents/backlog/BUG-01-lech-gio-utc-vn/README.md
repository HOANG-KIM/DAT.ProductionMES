- **Trạng thái:** ✅ Xong

## Ghi chú xử lý

**19/08/2026 — BẢN SỬA LẦN 2 (thay thế cách tiếp cận lần 1), sau khi người dùng đổi ý dứt khoát**: sau khi thấy bản vá "Z" (lần 1, giữ UTC thật + quy đổi hiển thị), người dùng quyết định KHÔNG dùng UTC nữa cho 3 field nghiệp vụ `Scan.ScannedAtUtc`/`ReworkUnlock.UnlockedAtUtc`/`Lot.UpdatedAtUtc` — muốn "scan giờ nào, DB lưu đúng giờ đó, không quy đổi gì cả". Tên field GIỮ NGUYÊN (không đổi `...AtUtc`), chỉ đổi Ý NGHĨA sang giờ local hệ thống. KHÔNG đụng `RefreshToken`/`StationApiKey` (vẫn giữ UTC thật — JWT `exp` nội tại tự tính theo UTC theo RFC 7519, đổi sẽ gây lệch logic hết hạn phiên/API Key, rủi ro bảo mật đã cảnh báo và được người dùng đồng ý giữ nguyên). Cập nhật `Documents/API-Conventions.md` mục 10 (ghi ngày 19/08/2026) mô tả ngoại lệ này. Các file đã sửa: (1) Infrastructure — bỏ `.HasConversion(new UtcDateTimeValueConverter())`/`NullableUtcDateTimeValueConverter` khỏi `ScanConfiguration.cs`/`ReworkUnlockConfiguration.cs`/`LotConfiguration.cs` (giữ nguyên converter ở `RefreshTokenConfiguration.cs`/`StationApiKeyConfiguration.cs`, giữ nguyên file `UtcDateTimeValueConverter.cs`); (2) Application — đổi `DateTime.UtcNow` → `DateTime.Now` khi ghi 3 field tại `ScanService.cs` (2 chỗ: nhánh OK/từ chối và `CreateNgAsync`), `ReworkUnlockService.cs`, `LotService.cs`; gỡ `.ToLocalTime()` đang giả định field là UTC tại `AndonBoardService.cs` (tránh double-shift +7h); **phát hiện thêm ngoài checklist ban đầu** và sửa luôn `ProductionReportService.cs` (dùng `query.FromUtc`/`ToUtc` so sánh trực tiếp + `.ToLocalTime()` để tính PLAN cumulative theo `ProductionPlan.StartTime` — nếu không sửa sẽ double-shift khi `web-admin` đổi cách gửi `from`/`to`), cập nhật lại 1 unit test tương ứng (`ProductionReportServiceTests.GetReportAsync_KhoangThoiGianDaQua_AC2...`, bỏ `.ToUniversalTime()`); (3) Station.Wpf — gỡ `.ToLocalTime()` tại `ReworkUnlockViewModel.cs`; (4) web-admin — đổi `range[i].toISOString()` → `range[i].format('YYYY-MM-DDTHH:mm:ss')` (không quy đổi UTC) tại `LotReportTab.tsx`/`LineReportTab.tsx` (4 dòng, đã grep xác nhận toàn bộ); (5) Domain — cập nhật XML doc `Scan.cs`/`ReworkUnlock.cs`/`Lot.cs` phản ánh đúng ý nghĩa mới (giờ local, không phải UTC). Xác nhận KHÔNG cần migration mới: `dotnet ef migrations add CheckNoOp2` sinh `Up`/`Down` rỗng, đã xoá ngay sau khi kiểm tra. Build `dotnet build ProductionMES.sln` sạch 0 error; `dotnet test tests/ProductionMES.Application.Tests` 253/253 pass (1 test ban đầu fail do hệ quả sửa `ProductionReportService.cs`, đã sửa lại đúng hành vi mới); `web-admin`: `npm run lint` sạch, `npm run build` pass. **Xác minh qua HTTP thật**: chạy `ProductionMES.Api` (profile https), login `POST /api/v1/auth/login`, gọi `GET /api/v1/scans/history` — response JSON trả `"scannedAtUtc":"2026-08-17T07:28:58.739677"` (KHÔNG còn hậu tố "Z", ngược lại hoàn toàn so với lần sửa 1) và `StationApiKey.createdAtUtc` vẫn giữ `"Z"` (`"2026-08-17T07:28:26.974789Z"`) — đúng đối tượng chốt phạm vi. Không tạo được bản ghi scan MỚI qua HTTP để đối chiếu chính xác giờ hệ thống hiện tại (cần reissue StationApiKey — hành động có tính huỷ dữ liệu cũ trên DB dev thật, bị chính sách an toàn chặn) — đã dừng đúng lúc thay vì tìm cách vượt qua, tin cậy vào build/test pass + review code (chỉ đổi `DateTime.UtcNow`→`DateTime.Now`, không còn logic quy đổi nào khác).
